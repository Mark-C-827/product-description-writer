# Benefit Translation

The core move of PDP copy: turn a spec into a reason to care.

## The formula

> **[Spec]** , which means **[concrete consequence for the buyer]**

The spec buys credibility. The consequence creates desire. Drop either half and
the bullet fails: spec alone is a datasheet, benefit alone is a claim nobody
believes.

```
316 stainless steel  →  which means it won't rust in a salt-air bathroom
61 HRC steel         →  which means you sharpen twice a year, not twice a month
8-hour battery       →  which means a full transatlantic flight with charge to spare
OEKO-TEX certified   →  which means it's tested free of harmful substances against skin
```

## Worked progression

| Level | Example | Value |
| --- | --- | --- |
| Feature | "316 stainless steel" | Credibility only |
| Vague benefit | "Corrosion resistant" | Says nothing felt |
| Concrete benefit | "Won't rust in a salt-air bathroom" | Buyer can picture it |
| Emotional payoff | "Still looks new after years by the coast" | Buyer can want it |

Aim for the third row on every bullet. Reach for the fourth only where the
category earns it (gifts, beauty, home) - forcing emotion onto hardware reads
as dishonest.

## Sentence patterns

Rotate these so bullets do not sound machined:

1. **Which means:** "316 stainless, which means it won't rust in a salt-air bathroom."
2. **So that:** "61 HRC steel holds its edge, so you sharpen twice a year instead of twice a month."
3. **Because:** "Sealed seams, because a leaking seam is the reason most bags get returned."
4. **Without the usual cost:** "Cuts a ripe tomato cleanly - without the sawing you do now."
5. **Time/framing shift:** "Eight-hour battery: a full workday, not a morning."
6. **Comparison:** "Half the weight of a cast-iron skillet, same sear."

## Finding the benefit when the spec looks dry

Ask, in order:

1. **What does this prevent?** (failure, annoyance, cost, maintenance)
2. **What does this save?** (time, money, effort, space, steps)
3. **What does this make possible** that the alternative does not?
4. **Who specifically stops worrying** because of this?
5. **What is the felt moment** - what do they notice, and when?

If all five come up empty, the spec is not a benefit. Drop it and log why in
"Notes to merchant." Dropping a spec is a legitimate outcome; padding it into a
fake benefit is not.

## Categories of benefit

Rotate across these so the bullet list covers the decision, not just the
product:

- **Performance** - does the job better/faster
- **Durability** - survives the use case
- **Ease** - fewer steps, less skill required
- **Fit / compatibility** - works with what they already own
- **Care / maintenance** - low upkeep
- **Comfort / feel** - sensory, in-hand, on-body
- **Risk reduction** - warranty, returns, guarantees
- **Identity** - what owning it says (use sparingly, category-dependent)

## Failure modes

| Failure | Bad | Fix |
| --- | --- | --- |
| Spec with no "which means" | "316 stainless steel construction" | Add the consequence |
| Benefit with no proof | "Incredibly durable" | Attach the spec that makes it true |
| Adjective stack | "Premium, high-quality, durable steel" | Delete; name the spec instead |
| Vague magnitude | "Long battery life" | "8-hour battery" |
| Restating the category | "A knife that cuts" | Name the transformation |
| Benefit for the wrong person | "Lab-tested to 0.01mm tolerance" (for home cooks) | Translate to what tolerance buys them |
| Forced emotion | "Feel the joy of stainless steel" | Cut it |

## Exercises

- Take one spec. Write the benefit three ways. Keep the most concrete.
- Read a bullet and ask "so what?" twice. If the second answer is thin, the
  bullet is thin.
- Cover the benefit halves. If the remaining specs read like a supplier
  datasheet, that is fine - it means the specs are doing their job. Cover the
  spec halves; if the benefits still sound convincing, you are probably making
  claims you cannot prove.
